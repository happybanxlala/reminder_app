1. 主頁上的「新增事項」浮動按鈕所導向的頁面已過期，請導向到新的頁面。

2. 在建立新的事項時，我認為 `warningAfter` / `dangerAfter` / `warningBefore` / `dangerBefore` 等欄位，用戶仍然難以快速思考並輸入資料。就著各類型的事項提出例子
    - 例子一(固定節奏)：到外婆家打掃，每週循環，可於星期五至日期間完成。所以實際上有3天的時間可以完成這件事。
    
    ```資料輸入：
    //...
    type:固定節奏
    scheduletype: weekly
    anchorDate:2024-05-01
    dueDate:2024-05-03
    ```

    用戶輸入了anchorDate和dueDate，系統(設計者)是否可以為用戶預設 warningBefore和dangerBefore的值？

    - 例子二(彈性節奏)：為飲水器換濾心，濾心的使用壽命約為3星期(21天)

    ```資料輸入：
    //...
    type:彈性節奏
    anchorDate:2024-05-01
    ```

    如果用戶再輸入的資料是[21]天，系統(設計者)可以為用戶預設 warningAfter和dangerAfter的值？

    - 例子三(庫存)：家裡的衛生紙庫存，當庫存量低於某個數值時。

    ```資料輸入：
    //...
    type:庫存
    duration: 10
    anchorDate:2024-05-01
    ```

    如果用戶再輸入的資料是資源的使用速率(例如每天使用1包)，例如高速／中速／低速，系統(設計者)可以為用戶預設 warningBefore和dangerBefore的值？
    
    ＝＝＝
    - 看完這些例子，我認為系統(設計者)可以根據用戶輸入的資料，預設 warningAfter / dangerAfter / warningBefore / dangerBefore 的值，並且在用戶建立事項後，提供一個編輯這些值的頁面／進階設定，讓用戶可以根據自己的需求調整這些值。
    - 用戶亦可以透過設定(setting page)的頁面修改內建的預設值。

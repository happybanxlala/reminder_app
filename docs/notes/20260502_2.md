# 背景問題

目前資料模型或建立事項流程中，可能存在以下欄位：

- `warningAfter`
- `dangerAfter`
- `warningBefore`
- `dangerBefore`

這些欄位對工程上有用，但對一般使用者來說太抽象。

使用者在建立事項時，不應該需要思考：

- 幾天後進入 warning？
- 幾天後進入 danger？
- 幾天前 warning？
- 幾天前 danger？

使用者真正理解的是：

- 這件事多久一次？
- 這件事可以在哪幾天完成？
- 這東西大約可用多久？
- 這東西消耗速度快不快？
- 什麼時候開始提醒？
- 什麼時候算太遲？

所以請把這些欄位重新定位為「系統內部提醒策略參數」，而不是主要建立流程的輸入欄位。

## 1. 新增或整理 Attention Policy / Reminder Urgency Policy

請在 domain model 中加入一個語意清楚的提醒策略模型。

命名可選其一，請根據現有 repo 命名風格決定：

- `AttentionPolicy`

它應該包裝以下欄位：

```dart
class AttentionPolicy {
  final int? warningAfterDays;
  final int? dangerAfterDays;
  final int? warningBeforeDays;
  final int? dangerBeforeDays;
  final AttentionPolicySource source;
}
```

也可以根據現有架構使用 `Duration?`，但請保持 serialization / persistence 穩定。

enum AttentionPolicySource {

用途：

* `userCustomized`：使用者曾在進階設定中手動修改

請避免讓使用者自訂後，又被新的系統預設覆蓋。

# 三種事項類型的預設推導規則

請根據 item type / schedule type / 使用者輸入，自動產生 `AttentionPolicy`。

---

## A. 固定節奏事項 Fixed Rhythm

例子：

```dart
type: fixedRhythm
scheduleType: weekly
anchorDate: 2024-05-01
dueDate: 2024-05-03
```

語意：

* 每週循環
* 可於星期五至星期日之間完成
* 實際完成窗口是 3 天

系統應該根據 `anchorDate` 和 `dueDate` 推導：

```dart
warningBeforeDays
dangerBeforeDays
```

建議預設：

```dart
warningBeforeDays = availableWindowDays - 1
dangerBeforeDays = 0
```

例如：

```dart
anchorDate: 2024-05-01
dueDate: 2024-05-03
availableWindowDays = 3

warningBeforeDays = 2
dangerBeforeDays = 0
```

語意是：

* 可做窗口開始時進入 warning
* dueDate 當天進入 danger

UI 不應顯示：

```text
warningBefore = 2
dangerBefore = 0
```

而應顯示類似：

```text
星期五開始提醒
星期日是最後期限
```

請注意：

* 如果完成窗口只有 1 天，warning / danger 需要合理處理。
* 如果完成窗口很長，例如 7 天以上，可以使用比例推導。
* 請避免出現 warning 比 danger 還晚的情況。
* 請避免負數。
* 請加入基本測試。

建議規則：

```dart
if availableWindowDays <= 1:
  warningBeforeDays = 0
  dangerBeforeDays = 0

if availableWindowDays >= 2 && availableWindowDays <= 3:
  warningBeforeDays = availableWindowDays - 1
  dangerBeforeDays = 0

if availableWindowDays >= 4 && availableWindowDays <= 7:
  warningBeforeDays = min(3, availableWindowDays - 1)
  dangerBeforeDays = 1

if availableWindowDays > 7:
  warningBeforeDays = ceil(availableWindowDays * 0.5)
  dangerBeforeDays = max(1, ceil(availableWindowDays * 0.2))
```

---

## B. 彈性節奏事項 Flexible Rhythm

例子：

```dart
type: flexibleRhythm
anchorDate: 2024-05-01
expectedIntervalDays: 21
```

語意：

* 飲水器濾心大約可以用 21 天
* 到第 21 天左右應該更換

系統應該根據 `expectedIntervalDays` 推導：

```dart
warningAfterDays
dangerAfterDays
```

建議預設：

```dart
warningAfterDays = round(expectedIntervalDays * 0.8)
dangerAfterDays = expectedIntervalDays
```

例如：

```dart
expectedIntervalDays = 21

warningAfterDays = 17
dangerAfterDays = 21
```

UI 應顯示：

```text
約第 17 天開始提醒
第 21 天建議處理
```

而不是顯示：

```text
warningAfter = 17
dangerAfter = 21
```

請注意：

* `expectedIntervalDays` 很短時要有合理下限。
* `warningAfterDays` 不應大於 `dangerAfterDays`。
* `dangerAfterDays` 通常等於使用者輸入的壽命 / 週期。
* 請加入測試。

建議規則：

```dart
if expectedIntervalDays <= 1:
  warningAfterDays = 0
  dangerAfterDays = 1

if expectedIntervalDays <= 3:
  warningAfterDays = max(1, expectedIntervalDays - 1)
  dangerAfterDays = expectedIntervalDays

if expectedIntervalDays > 3:
  warningAfterDays = round(expectedIntervalDays * 0.8)
  dangerAfterDays = expectedIntervalDays
```

---

## C. 庫存事項 Stock / Inventory

例子：

```dart
type: stock
anchorDate: 2024-05-01
estimatedDurationDays: 10
usageSpeed: medium
```

語意：

* 家裡衛生紙大約還能用 10 天
* 使用速度是中等

系統應該先推導：

```dart
estimatedEmptyDate = anchorDate + estimatedDurationDays
```

再根據 `usageSpeed` 推導：

```dart
warningBeforeDays
dangerBeforeDays
```

建議新增 enum：

```dart
enum UsageSpeed {
  low,
  medium,
  high,
}
```

建議預設：

```dart
low:
  warningBeforeDays = 2
  dangerBeforeDays = 1

medium:
  warningBeforeDays = 3
  dangerBeforeDays = 1

high:
  warningBeforeDays = 5
  dangerBeforeDays = 2
```

例如：

```dart
estimatedDurationDays = 10
usageSpeed = medium

estimatedEmptyDate = 2024-05-11
warningBeforeDays = 3
dangerBeforeDays = 1
```

UI 應顯示：

```text
預計可用到 5月11日
5月8日開始提醒補貨
5月10日加強提醒
```

請注意：

* 如果 `estimatedDurationDays` 小於預設 warningBeforeDays，要自動縮短 warningBeforeDays。
* 不要讓 warningBeforeDays 大於整個可用天數。
* 不要讓 dangerBeforeDays 大於 warningBeforeDays。
* 請加入測試。

# Setting Page：全局提醒風格

請準備或實作一個全局設定概念：

```dart
enum ReminderTone {
  gentle,
  standard,
  early,
  urgent,
}
```

或者根據現有命名使用更合適的名字。

語意：

* `gentle`：接近期限才提醒
* `standard`：平衡提醒
* `early`：較早提醒
* `urgent`：較早進入強提醒

如果目前 Setting Page 還未準備好，不需要一次完成 UI，但至少請：

1. 在 domain / config 層預留模型
2. 有 default value：`standard`
3. 推導 AttentionPolicy 時可以接受這個設定
4. 加入測試

## ReminderTone 對不同類型的影響

### Flexible Rhythm

```dart
gentle:
  warningAfterDays = round(expectedIntervalDays * 0.9)
  dangerAfterDays = expectedIntervalDays

standard:
  warningAfterDays = round(expectedIntervalDays * 0.8)
  dangerAfterDays = expectedIntervalDays

early:
  warningAfterDays = round(expectedIntervalDays * 0.65)
  dangerAfterDays = expectedIntervalDays

urgent:
  warningAfterDays = round(expectedIntervalDays * 0.6)
  dangerAfterDays = round(expectedIntervalDays * 0.9)
```

### Fixed Rhythm

可根據 availableWindowDays 調整：

```dart
gentle:
  warningBeforeDays = min(1, availableWindowDays - 1)
  dangerBeforeDays = 0

standard:
  warningBeforeDays = availableWindowDays - 1
  dangerBeforeDays = 0

early:
  warningBeforeDays = availableWindowDays - 1
  dangerBeforeDays = min(1, availableWindowDays - 1)

urgent:
  warningBeforeDays = availableWindowDays - 1
  dangerBeforeDays = min(1, availableWindowDays - 1)
```

請按實際語意修正，重點是：

* standard 是目前主要預設
* gentle 不要太早提醒
* early 比 standard 更早開始提醒
* urgent 較早進入 danger

### Stock / Inventory

```dart
gentle:
  warningBeforeDays = 2
  dangerBeforeDays = 1

standard:
  warningBeforeDays = 3
  dangerBeforeDays = 1

early:
  warningBeforeDays = 5
  dangerBeforeDays = 2

urgent:
  warningBeforeDays = 7
  dangerBeforeDays = 3
```

如果加上 `usageSpeed`，可以把 `ReminderTone` 和 `UsageSpeed` 合併計算，但請保持邏輯簡單、可測試。

# 測試要求

請至少加入以下測試：

## Fixed Rhythm

1. 3 天完成窗口：

   * warningBeforeDays = 2
   * dangerBeforeDays = 0

2. 1 天完成窗口：

   * 不出現負數
   * warning / danger 合理

3. 7 天完成窗口：

   * warning / danger 合理
   * warning 不晚於 danger

## Flexible Rhythm

1. expectedIntervalDays = 21：

   * standard tone 下 warningAfterDays = 17
   * dangerAfterDays = 21

2. expectedIntervalDays = 1：

   * 不出現 0 以下或不合理結果

3. urgent tone：

   * warning 比 standard 更早
   * danger 可以比 standard 更早

## Stock

1. estimatedDurationDays = 10, usageSpeed = medium：

   * warningBeforeDays = 3
   * dangerBeforeDays = 1

2. estimatedDurationDays = 3, usageSpeed = high：

   * warningBeforeDays 不應大於 estimatedDurationDays
   * dangerBeforeDays 不應大於 warningBeforeDays

3. low / medium / high 有不同結果
